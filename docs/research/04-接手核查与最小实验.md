作者在线逻辑在 `sources/ReBalance/modeling_utils/modeling_qwen2_dynamic_3D.py`：

- 第1154行：词表中包含 `ĊĊ` 的 token 作为换段边界。
- 第1242–1255行：维护 `<think>`/`</think>` 状态，只在 think 内的边界注入。
- 第1274–1299行：累计前次输出的最大概率，排除被采样为边界的 token；使用**算术平均**，相邻步骤方差为 `(c_current-c_previous)^2/4`，首步方差为0。
- 第1550–1632行：构造并使用实际动态函数，详见下面的数值问题。
- 第1671–1674行：从原始 logits 的 softmax 得到最大概率，位于外部 temperature/top-p 采样之前。

`sources/ReBalance/transformer_inference_steer_dp.py` 第155–181行采样时记录的是经过 temperature/top-p 处理后**被采样 token** 的概率；第360–379行的 `sentence_confidences` 是输出后的分段统计。即使这里出现指数化平均 logprob，也不能将它当作在线最大概率控制器或论文式(1)的直接实现。

层映射有源码依据：作者在 decoder 循环进入索引19前加向量（`modeling_qwen2_dynamic_3D.py:881`）；EasySteer 在层输出处干预（`sources/EasySteer/vllm-steer/vllm/steer_vectors/controllers.py:312`），加性增量可保留 Qwen 的分离 residual，所以对应输出层18。这支持映射设计，尚不代表跨 Transformers/vLLM 的逐 token 数值等价已经实测。

## 关键问题：两个锚点相同，函数整体不同

作者代码：

```python
def build_F(q25, q75, low_val=-3.0, high_val=0.0, tau=0.1):
    ...
F1 = build_F(q25c, q75c, low_val=low_val_1, tau=high_val_1)
```

定义在 `modeling_qwen2_dynamic_3D.py:1550`，调用在第1589行。调用没有传 `high_val`，所以实际是 `high_val=0.0, tau=0.01`。

适配版 `sources/EasySteer/vllm-steer/vllm/steer_vectors/rebalance.py:88` 设 `high_val_1=0.01`，第92–101行将同一个0.01同时用于形状拟合的上界和目标值，以及截距/斜率。这会改变 tanh 曲线形状。

## 性能开销候选：已定位调用，尚未测占比

1. `model_runner.py:1152` 每解码步将 logits 转 FP32，再计算全词表 `amax + logsumexp + exp`。其位置在采样处理前，可得到作者所需的原始最大概率；不能直接复用温度或 top-p 处理后的概率。
2. `steer_vector_utils.py:170` 起每步按请求配置分组，新建位置张量，执行 `index_select/index_copy_/isin/where`。第213行无条件计算整组候选系数，之后才以 `ready` 选择写回；非边界步也支付候选函数计算成本。
3. `rebalance.py:92` 每次调用重复求解与请求状态无关的 k（80次 CPU 二分）和常量；第133–134行还创建基准点张量。这些适合先测量、后缓存，缓存时必须保持已选定版本的数值行为。
4. `steer_vector_utils.py:574` 的 token 系数展开、触发位置及 graph mask 更新在每步继续执行。`in_graph` 不等于整个控制器、采样和状态反馈都被纳入 CUDA graph。

全词表归约、CPU 调度、GPU 小算子、图 mask 准备，以及生成长度/批处理尾部共同影响总耗时。当前没有 profiler 证据支持按优先级断言其中任何一项占主导。

## 下一个最小实验

先补函数正确性证据，再做小样本系数诊断；不立即实现几何平均版或拟合新函数。

**E0：无模型函数与状态验收。** 本次已完成现版本的函数差异审计。下一次修正时冻结旧版本，补中间区间和阈值两侧的作者函数对照；另验证连续边界、首段、`</think>`、请求换序、移除/复用、混合 baseline 请求。以FP32容差和符号一致为验收条件；不以两个锚点替代完整函数对照。纠正作者代码对齐属于复现修复，不属于拟合新函数。

**E1：20题诊断。** 服务器验收后使用既有 GSM8K 子集的固定20题，仅作工程诊断；不用于拟合。保持作者向量、层18、prompt、seed42、temperature0.7、top_p0.95、max_tokens4096不变。冻结旧动态版作为历史参考，修正版单独命名和保存结果，避免覆盖已有200题文件。

- 先为待测版本比较“关闭诊断”和“开启诊断”，检验逐题 token IDs、答案、截断和实际系数轨迹不受记录影响；保存实际 token IDs，当前结果脚本只保存文本和 token 数，不能据此直接声称 token IDs 一致。
- 只在**实际注入边界**汇总 `request_id/step_index/c/v/alpha/step_tokens/in_think`；区分候选系数、状态更新与真正注入。用 GPU 累计直方图和有限采样缓冲，结束后一次导出，避免逐 token `.item()` 和写文件；记录缓冲溢出情况。
- 报告负/近零/正系数比例、分位数、饱和比例、符号切换、首段/后续段差异，同时给出按边界汇总和每题等权统计。关联历史改善/退化题只作描述，不据此调参。
- 独立做短 CPU/CUDA profiler 窗口，分开记录 logits 置信度归约、控制函数、状态读写、系数/掩码准备；记录各步活跃请求数、总解码步数和尾部长请求。profiler 运行的耗时不计作性能主结果。
- 正式比较该小样本时排除启动/预热，先用1–2道固定工程题预热，再对同版计时做3次短重复，报告中位数及范围。不要直接将20题时间线性外推到200题。

**E2：只根据诊断选择一个优化。** 例如缓存不变常量，或融合状态更新/全词表归约；先守住实际输出等价性。若要比较控制策略本身，再引入相同 think 约束的固定-1对照。不要同时改均值定义、向量范数、触发规则和函数参数。

200题以上评测、论文公式实现和独立校准集拟合均等待后续确认。保留测试集不参与函数挑选；若现有200题用于反复工程探索，也应与未来最终保留集明确分开。
