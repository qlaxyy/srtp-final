## 3．哪些信号互补，哪些会冲突

原控制器仍可能留下：高置信度错误循环、没有空行的长段、能局部计算却迟迟不转入答案、以及前面干预改变后的新冗余。交接中既有“高置信度重复”也有“高置信度有效求和”，不能凭高c低v给冗余或正确性贴标签。本轮只读动态100题再次确认触发词常见，但没有恢复其完整logits，无法CPU推算SyncThink实际触发机会。

SyncThink的结束排名包含ReBalance未显式读取的**特定token竞争信息**；即使最大概率和熵相同，交换词表身份也能改变结束排名。两者仍共享受干预后模型分布：ReBalance可能直接提高结束排名，所以组合增益可能只是同一收敛变化的重复放大。SyncThink的低熵偏好也会误认自信错误为完成。

CGRS的试答分布是在另一提示条件下测得，比主链局部置信度多了一类信息；但它衡量“模型如何确信地写出试答”，不保证其推导／答案正确。原向量的词法标签已混入反思／转换，抑制同类词可能重复干预；原ReBalance高置信度区域可能施加正方向以鼓励纠正，而CGRS同时禁止“Wait”，动作可能冲突。负方向压缩再加硬禁词也可能阻断唯一有效纠错路线。

**实际时序（main）**：`model_runner.py:1142–1196`在已受激活干预的隐藏状态上算logits → 先取原始max概率 → grammar → sampler的logit bias／penalty／bad words／temperature／min_p／top_k/top_p → 采样 → `observe_sample`。`steer_vector_utils.py:314–346`排除分隔token累积，边界到达后计算c／v；`_record_scales:348`把强度写给本次采出token的下一输入位置。首段通常没有注入；`initial_coef=-1`不能解释成首次提示末尾施加−1。

两新模块若将来并用，必须在**任何logits修改前的同一快照**各自读取信号，先决定动作，再应用。CGRS先屏蔽竞争词再算SyncThink，会机械降低结束排名数值并改变熵；CPU三token反例中，结束排名1→0、结束概率.30→.75，足以伪造“就绪”提升。反过来先强制结束再测C会得到近乎零熵，也是自证循环。温度正数不改变原始rank，但改变熵；top_p改变支持集，不能作为原始置信度。ReBalance的max统计要保持原公式，不能被强制one-hot污染；新采样改变下一步前缀造成的分布变化则是策略真实效果，不能也声称隔离掉了。

无需为“交换激活注入和logit操作”增加实验组：隐藏层干预在logits产生前，自然有因果顺序；真要知道同前缀未注入的分布须另做反事实前向。首轮分别只组合一种新机制，不测试三者顺序。

规则：`t=已接受生成token数+1`，排除prompt、虚假prefill采样、KV重放；从第一个有效decode开始、仅think阶段。rank从0计，logit相同按token ID升序；全LM输出词表、自然对数、原始temperature=1分布，使用FP32稳定logsumexp／归约，不能用top-k日志近似。rank用比较计数，不全排序。模型填充词表如有预置无效logit，必须明确有效支持掩码；NaN/+inf／无有效支持拒绝，`-inf`质量按0处理。CPU oracle只接受有限输入，GPU适配另测无效支持处理。

触发时当前这一采样位置只允许`</think>`（本分词器ID151649）；随后继续同一KV、同一请求正常生成答案，结束标记也占16000预算，不能在budget之外免费追加。保持原R统计得到的max值；R观察真实结束ID后关闭实际注入。S的`thinking_closed`应不可逆，答案里再输出`<think>`不重启S。不额外采一次token后再替换，否则采样日志／penalty／KV会不一致。首版本拒绝grammar、非默认penalty/bad_words、speculative decoding、多GPU、prefix caching及probe组合，不添加不必要的修复路径。

状态按`request_id + generation_instance`拥有，槽位只作索引：保存prompt长度、已接受生成数、关闭标志、首次强制位置及计数、配置指纹；有效token提交单调一次。重新预填充不推进时钟或再触发；重放到历史位置复用已接受token与R历史强度，不能按当前系数重算旧KV。暂停完整保存，换槽恢复同状态；取消／完成丢弃，复用槽位清零。S无额外RNG；C若后续实现采用独立、按题哈希／种子／位置索引的随机流，不能消费主采样RNG。

统一1.5B BF16，temperature=.7、top_p=.95、seed42、max_model_len32768、max_num_seqs128、max_num_batched_tokens32768、GPU memory .90；首版**同步调度**、关闭chunked prefill／prefix caching／推测解码，原层20、raw向量、fit，first-step与其他探索全部关闭。同步选择用于减少首次生命周期整合范围，四组一致；不把03中异步吞吐数字视为保证。每题相同seed不保证不同生成长度／调度下逐token共用随机数，记录引擎版本与实际调度。

筛选事前门槛：RS相对R、S**分别**满足平均思考及平均总token严格减少（无最低5%要求）、正确数不低、触顶不多；作者判分全齐且实际有强制动作。这样只是“胜过两个单项的初步信号”，不叫协同或证明无损。若仅胜过较弱单项，记为未满足组合价值；S优于R而RS无增益，则应考虑单机制，不宣称组合成功。没有对比U也能比较三组优势，但不能计算下面的交互，因此本轮保留U。

固定主交互尺度：每题生成总token的加法差，`I_T=mean(T_RS-T_R-T_S+T_U)`，负值表示组合比两单项节省量之和还多；思考token同式为次指标。例U100、R80、S90、RS75，RS虽比两个单项都短，I=+5，仍非超加性；RS65才有I=−5。正确率另算`I_A=A_RS-A_R-A_S+A_U`，不把两个指标硬混成任意效用，也不把跨题集比例相加。乘法尺度`log(meanT_RS*meanT_U/(meanT_R*meanT_S))`只作预定敏感性报告，不能哪个显著选哪个。

确认报告使用固定seed20260912、10000次**题级配对bootstrap**，每次共同抽U/R/S/RS行；报告每个差值、比值、I_T的95%区间，另报正误不一致数／精确McNemar作描述。单seed区间不包含全部采样和部署波动；小样本零退化也不证明总体零风险。对→错／错→对题号必须列出，不只看净正确数。
