# ReBalance × S64-soft2：保留继续推理机会

**判断：先把强制结束改成有限的结束倾向，值得做一次小规模筛选；目前没有证据证明新版本达到正确率下降不超过2个百分点。** 用户已明确接受相对原ReBalance最多下降2个百分点。旧S64确认失败与全量退化结论保留，本次是新候选，不是旧实验改判。

## 依据与取舍

旧S64观察当前分布的熵和`</think>`排名，触发就将其他所有logit置为负无穷。低熵只能说明模型对“下一个token”集中，可能集中在继续计算的数字上，不能说明结束token可靠。S64的64是排名门槛中的时间项上限，**不是只允许思考64个token**。

本次只重读已消费的训练验证轨迹，并核对原始结果、作者判分和逐题哈希。MATH200中组合触发194题，原R对而组合错22题，其中19题第一次触发时结束token不是top1；全部触发中174题不是top1。GSM8K200对应200次触发、16题受损，其中7题不是top1，全部触发中47题不是top1。MATH训练6235第一次触发rank58、熵约0.00655，说明低熵也能伴随很靠后的结束排名。**这些是机制诊断，不能证明每题错误都由该条件造成。** 无保存logits，无法从旧输出计算新候选的反事实正确率。400题明确登记为本次开发材料，不能再称新独立确认。

保留一个候选：**S64-soft2**。不改ReBalance向量、层、拟合参数、步骤边界，不调S64的0.8或64；主要改变终止动作。没有将最小位移、CGRS或新的正确性分类器加入。

淘汰本轮的两个替代：①仅改64或熵权重，继续强制停止，未解决低熵的语义问题且成为旧题调参；②加入boxed或两次答案一致的门槛，增加文本解析、答案相似度和探测前向，仍不能认证正确。本轮不同时加入这些因素。

## 精确行为与采样顺序

1. ReBalance先在模型隐层按原步骤规则注入，得到原始logits `z`。
2. 原ReBalance缓存`max softmax(z)`；S64仍从同一份`z`计算自然对数熵、含token-ID平局规则的零基rank，触发规则完全不变：`rank <= floor(min(t,64)*exp(-0.8*H))`。ReBalance读取的不是未干预模型的反事实分布，而是**已有R隐层干预、尚未做结束偏置/温度/过滤**的分布。
3. 进入原采样器，依次温度0.7、原过滤top-p0.95。只有已通过过滤的结束token才可获得偏置。
4. 新开关`mode="soft"`且S64触发时，给保留下来的结束token加`ln(2)`。其余logit不变；若结束token已被过滤为负无穷，不复活它。**过滤不再重做**，然后只调用一次原有seeded Gumbel采样。
5. 观察真实采样token，更新R原统计及S64计数。只有实际采到`</think>`才关闭思考。后续仍允许模型生成正常答案，统一16000总生成上限。

若过滤后原结束概率为`q`，理想实数下新概率为`2q/(1+q)`。例如`q=0.1`变为约0.1818，模型仍有约81.82%的概率继续。`q=0`仍为0；原候选只剩结束token时`q=1`仍为1，这是原过滤本就决定的结果。其他继续token之间的相对概率不变。单步分布总变差上界约0.17157，**不是整条轨迹或正确率损失的上界**。实际BF16舍入需原生测试，不能把理想公式称逐位精确。

两倍是本次事前固定的保守设计选择，不是论文给定最优值；不进行倍数扫描。属于按S64思路改写的项目适配，不是官方SyncThink实现。

## 实现和隔离

[implementation.patch](implementation.patch)基于`c688b9c0328cbbad919e17b7665b8b489b5ef29f`，5个文件的改前、改后LF SHA256及补丁SHA256在[patch_manifest.json](patch_manifest.json)。**补丁尚未应用到共享源码或服务器**，应由执行对话在独立运行提交整合，保持本B线命名空间：

| 文件 | 接口与改变 |
|---|---|
| `sources/EasySteer/vllm-steer/vllm/v1/worker/gpu/sample/hybrid_termination.py` | 增加soft模式；`read_apply`只登记当步候选，`apply_after_filter`消费一次ticket并修改结束列；保存first_bias、bias_count、filtered_trigger_count；旧hard模式仍可运行 |
| 同目录`sampler.py` | `__call__`和`sample`增加默认None的`after_filter`回调，严格置于top-k/top-p之后、Gumbel之前；soft拒绝greedy/FlashInfer未验路径 |
| `.../gpu/model_runner.py` | 仅存在soft请求及有效ticket时传递回调；原R置信度缓存顺序不变 |
| B线`run_batch.py` | 使用resolved文件内新题单；新协议的S/RS调用soft，工程比较采用首次实际bias位置；保存异步worker与已发布位置 |
| B线`grade_screen.py` | 增加两个soft2题单角色，继续原作者判分，核对逐题输入 |

不复制控制器。off路径不建立S64状态，也不调用回调。shadow不改logit。soft每步的ticket在下一次读取前清空、回调后立即消费；按请求ID绑定槽位，移除请求保存计数，新请求复用槽位时全部重置；关闭思考后不重开。分块预填充不计入接受token，前缀重算、推测、多卡、抢占与未验证恢复仍拒绝。异步可能产生一枚未发布尾token，worker计数保留，公开位置按真实输出裁剪，不混为多生成的正式token。

本补丁省去soft路径的整词表强制mask分配与回写，只改结束列；**仍需每步计算熵/rank，且更长思考可能增加时间，不承诺恢复基线速度**。先验证准确率/压缩是否值得保留，避免同时重写熵核引入新的行为差异。纯生成时间必须包含控制开销；CUDA统计/bias计时另列，Python调度在纯生成时间中，不能仅以核时间解释全部开销。
